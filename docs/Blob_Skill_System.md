# Skill System

> **담당** — 메커니즘을 바꾼다 · 무엇으로 죽이는가
> **근거** — poe2db.tw/kr (스킬 젬 / 보조 젬 / 정신력 젬 실목록 직접 확인)

수치(피해·지속시간·방어)는 이 문서에 없다. [`Combat_Baseline.md`](Blob_Combat_Baseline.md)가 유일한 출처다.
이 문서는 **무엇이 존재하는가와 그 규칙**만 정한다.

## 0. 획득 방식 전환 — 레벨업 선택에서 인자 파밍으로

**스킬은 레벨업 때 3장 중 고르는 것이 아니라, 드랍으로 줍는 실물 아이템이다.**
실물이 된 스킬을 **「인자(因子)」**라 부른다. PoE2의 스킬 젬에 해당한다.

| | 이전 | 현재 |
|---|---|---|
| 획득 | 레벨업 → 적재한 것 중 3장 제시 → 1장 선택 | **적 드랍으로 인자를 줍는다** |
| 장착 | 획득 즉시 자동 장착 | **유저가 소켓에 직접 끼운다** |
| 레이드 중 교체 | 불가 | **가능** (이미 낀 것도 갈아끼울 수 있다) |
| 런 종료 시 | 전부 초기화 | **추출 성공 시 보관** |
| 사망 시 | — | **들고 있던 인자 전부 소멸** |
| 각성 레벨의 보상 | 스킬 선택 | **소켓 개방** |
| 적재(Loadout) | 도감에서 6~11개를 미리 고른다 | **폐기.** 인자가 가방 공간과 무게를 쓴다 |
| 도감 | 보유 목록 | **해금 기록** (드랍 풀 · 제작). 실물 보유와 분리 |

**왜 바꿨는가** — 추출 루팅 게임에서 가장 강한 동사는 「줍는다」다.
레벨업 선택은 그 동사를 레벨 게이지 뒤로 숨긴다.
드랍으로 바꾸면 전투의 보상이 곧바로 손에 잡히고,
「어느 Core의 어느 소켓에 끼울까」라는 새 결정이 생긴다.

**잃은 것** — 「3장 중 고르는 순간」의 재미.
**얻은 것** — 찾는 과정, 배치의 결정, 그리고 **인자에도 걸리는 추출 게임의 긴장.**

## 0-1. 이름 충돌 주의 — 「관통」은 두 개다

프로젝트에 「관통」이라는 말이 두 군데에서 서로 다른 뜻으로 쓰인다.
방치하면 코드·UI·문서가 조용히 어긋난다.

  · Support 스킬 **「관통」**       = 투사체가 적을 뚫고 지나간다 (Pierce)
                                     ProjectileBehaviourType.Pierce
  · 전투 수치 **「방어 관통」**     = 방어도 감쇠 판정에 쓰는 레벨 0~6
                                     EquipmentStatType.ArmourPenetration

  [규칙]
    1. 약어 「관통」은 언제나 Pierce를 뜻한다.
    2. 후자는 문서·코드·UI에서 반드시 **「방어 관통」**으로 풀어 쓴다.
    3. **스킬은 방어 관통을 올리지 않는다.** 그것은 장비의 축이다. (14절 9번)

  ※ 마스터 프롬프트 1절 "증상과 원인을 구분한다"의 사례와 같은 문제다.
    이름이 겹치면 그 자리를 때우지 말고 어느 시스템의 것인지부터 정한다.

## 1. 명명 원칙

1. poe2db 한글판의 실존 젬명을 그대로 쓴다.
2. 이름이 같은 젬이 없으면 효과가 가장 가까운 실존 젬의 이름을 차용한다.
3. 대응 메커니즘 자체가 없으면 기능을 삭제하지 않고, 뜻이 즉시 전달되는
   이름으로 짓고 그 사실을 문서에 명시한다.

예외 — 스킬이 아니므로 이 원칙의 대상이 아니다.
   장비 아이템명 (Equipment_System.md)
   몬스터 등급·속성명 (Hunting_System.md)

## 4. 상태 어휘

이 절이 **상태 이름의 원본**이다. 다른 문서가 어긋나면 이쪽을 따른다.
반대로 **초당 피해·지속시간·중첩 수치는 이 문서가 정하지 않는다.**
Combat_Baseline.md 7절이 유일한 출처다.

  ※ 상태이상 피해는 **방어도 보정을 받지 않는다.** (전투 기준 3-3절)
     이것이 "단단한 적을 스킬로 우회한다"를 성립시키는 유일한 장치이며,
     몬스터 속성 「갑각」의 대응 수단이 도트 빌드가 되는 이유다.

  ※ 상태이상의 **해제와 면역은 전부 장비(각인)의 몫이다.**
     스킬은 거는 쪽, 장비는 막는 쪽이다. (14절 8번)

## 4-1. 전투의 3층 구조

무기·Core·Support가 각각 다른 질문에 답한다. 한 층이 다른 층의 역할을 가져가면 나머지가 죽는다.

| 층 | 소재 | 답하는 질문 | 예 |
|---|---|---|---|
| **무기** | 장비 (파밍·제작) | 얼마나 세게 · 빨리 · 멀리 쏘는가 | 기본 피해 · 발사 간격 · 유효 사거리 · 방어 관통 |
| **Core** | 스킬 | **무엇을 싣는가** | 화염 → 점화 / 서리 → 동결 |
| **Support** | 스킬 | **어떻게 날아가는가** | 관통 · 갈래 · 사슬 · 부메랑 |

물총에 화염 Core를 얹으면 불을 쏘고, 레일건에 같은 Core를 얹으면 관통하는 불을 쏜다.
→ 무기 상세는 [`Equipment_System.md`](Blob_Equipment_System.md)

## 6. 보조 스킬 (Support) — 35

[6-1. 통화(Cost) — 7종]
직접 피해 수치 감소는 사용하지 않는다.

  · 탄막 밀도    : 발사 간격 증가, 탄 수 감소
  · 유효 사거리  : 사거리·범위 축소 → 접근 강요 → 위험 증가
  · 조작 제약    : 행동 자체를 제약
  · 기능 배타    : "X를 이용하는 대신 X를 생성할 수 없다"
  · 투사체 속도  : 탄속 증감
  · 지속시간     : 상태이상·잔류물의 지속시간 증감
  · 즉시성       : 발동 지연, 즉발 → 지속 전환

  ※ CostType enum에 Damage 항목을 두지 않는다.

[8-1. 동시 장착 1개]
  전령은 5종 중 하나만 장착할 수 있다. Nucleus 같은 자원 시스템은 두지 않는다.

  근거 — 전령은 전부 "특정 상태의 적을 처치했을 때" 발동한다.
  한 런의 빌드는 보통 한 속성으로 수렴하므로, 2개를 들어도 실제로는
  하나만 작동한다. 자원 시스템을 만들어 계산하게 하는 것보다
  "5종 중 하나를 고른다"가 더 정직하고 UI도 단순하다.

  ※ v6의 Nucleus 100 / 전령 45 구조는 되살리지 않는다.
     유틸 8종이 전부 장비로 갔으므로 Nucleus가 "전령 vs 전령"만 재게 되어
     자원으로서 의미가 없다.

[8-2. 왜 전령만 스킬로 남는가]
  v7은 유지형 13종을 전부 폐지하고 장비로 넘겼다. 그중 유틸 8종
  (이동 속도·체력 재생·감지 거리 등)은 상시 능력치라 장비가 맞다.

  그러나 전령 5종은 다르다. "처치 시 연쇄 폭발"은 순수 전투 메커니즘이며
  상태 어휘(점화·동결·감전·중독·출혈)에 직접 연결된다.
  장비 옵션으로 옮기면 장비가 곧 스킬이 되어 두 시스템의 경계가 무너진다.

  → 전령은 Skill에 남는다. 상시 능력치는 장비가 담당한다. 경계는 유지된다.

[8-3. 조합에서의 위치]
  전령은 「밀집 서식」 레이드에서 최대 가치를 낸다.
  적이 분산된 구조에서는 처치 연쇄가 항상 강하지 않으므로,
  유저는 레이드 특성을 보고 전령을 적재할지 판단하게 된다.

## 9. 충돌 우선순위 큐

        Split  →  Pierce  →  Fork  →  Chain  →  Return

한 번의 충돌에는 단 하나만 해결된다.

| 단계   | 담당      | 기본값                              |
|--------|-----------|-------------------------------------|
| Split  | 파편 탄환 | 3갈래. 파편은 재분열하지 않는다     |
| Pierce | 관통      | 3체                                 |
| Fork   | 갈래      | 2갈래, 원 궤도 기준 ±60도           |
| Chain  | 연쇄      | 3회, 동일 적 재타격 불가            |
| Return | 부메랑    | 1회. 재타격이 허용되는 유일한 예외  |

[큐에 들어가지 않는 것]
  튕겨 쏘기       : 지형 충돌에서 발동. 적 충돌 큐를 소모하지 않는다
  다중 사격       : 발사 시점에 탄이 늘어난다
  추격            : 지속 유도(호밍). 충돌 시 재유도가 아니다
  투사체 가속/감속: 속도 변경일 뿐 충돌 판정이 아니다
  폭발 투사체     : 적중 지점에서 새 투사체를 만든다
  원거리 사격     : 거리 조건 효과

[배타가 자동 발생하는 구조]
  관통과 갈래를 둘 다 보유하면 한 충돌에서 관통만 해결된다.
  곱연산이 일어나지 않는다. 수치 인플레 없이 선택의 무게가 생긴다.

## 10. 합성 발사 (Composite Fire)

Core를 2개 보유해도 따로 발사하지 않는다. 한 발에 합쳐진다.

  부여 계열 Core → 그 탄이 부여할 상태
  소켓의 Support → 그 탄의 투사체 행동
  기폭 계열 Core → 투사체가 아니므로 합성 대상이 아니다. 독립 발동한다.

  예: 화염 Core + 소켓의 관통 = "관통하면서 점화시키는 탄 1발"

[채택 근거]
| 방식        | 탄 수 | 문제                                      |
|-------------|-------|-------------------------------------------|
| 동시 발사   | 2배   | 모바일에서 발열·드로우콜 부담이 가장 크다 |
| 교대 발사   | 1배   | 상태 부여 빈도 절반 → 부여 Core 체감 붕괴 |
| 주·보조 전환| 1배   | 전환 버튼이 하나 더 필요하다              |
| **합성**    | 1배   | —                                         |

[확정 규칙]
1. Core 개수는 탄 수에 영향을 주지 않는다. 탄이 늘어나는 것은 「다중 사격」뿐이다.
2. 부여 Core가 2개면 발사마다 번갈아 부여한다. (각 50% 빈도)
   동시 부여로 만들면 「원소 융합」(대가: 적용 빈도 절반)이 무가치해진다.
     - Core 2개 방식 : Core 슬롯을 쓴다 (대신 소켓 3개가 딸려온다)
     - 원소 융합 방식 : 소켓 1칸을 쓴다 (대신 Core 슬롯을 지킬 수 있다)
3. 기능 배타로 차단된 상태(번제 → 점화)는 탄에 실리지 않는다.
4. 태그 게이팅은 Core 단위를 유지한다.

[2번째 Core 슬롯]
  Lv7에 열린다. "Core 보유 상한 2개"는 상한이지 즉시 지급 보장이 아니다.

## 11. 인자(因子) — 실물이 된 스킬

53종의 스킬 정의는 그대로다. 바뀐 것은 **그것을 어떻게 손에 넣는가**뿐이다.

```
도감 (해금 기록, 영구)
   ↓ 해금된 것만 드랍 풀에 들어온다
레이드 중 적 드랍 → 인자를 줍는다
   ↓ 유저가 직접
소켓에 끼운다 → 즉시 작동
   ↓
추출 성공 : 창고로 간다       사망 : 들고 있던 인자 전부 소멸
```

### 11-1. 인자는 아이템이다

- **무게와 가방 칸을 쓴다.** 장비·전리품과 같은 인벤토리를 공유한다.
  → 출격 전에 *"인자를 많이 챙겨 화력을 확보할까, 가방을 비워 전리품 공간을 남길까"* 라는 결정이 생긴다.
  → 별도의 「적재」 개념이 필요 없어진다. 가방에 넣는 것이 곧 가져가는 것이다.
- **창고에 보관한다.** 대기실에서 창고의 인자를 꺼내 장착하고 출격한다.
- **사망 시 들고 있던 것 전부 소멸한다.** 장비와 같은 규칙이다.
  배울 규칙이 하나다 — **죽으면 들고 있던 것 전부.**

### 11-2. 도감은 「해금 기록」이지 「보유 목록」이 아니다

```
도감 = "이 인자가 존재한다는 것을 안다"  →  드랍 풀 · 제작 해금.  영구
인자 = 실물 아이템                        →  죽으면 잃는다
```

도감이 가득 차도 **인자 실물은 매번 다시 구해야 한다.**
도감은 "무엇이 나올 수 있는가"를 넓힐 뿐이다.

> 덕코프의 **설계도**와 같은 구조다. 설계도는 영구 해금이고 만든 물건은 죽으면 잃는다. [확인됨]

**해금 경로** — 희귀 이상 등급의 적이 「변이 샘플」을 드랍한다.
흡수한 뒤 추출에 성공하면 도감에 영구 등록된다. 실패하면 샘플만 잃는다.
(상세는 [`Hunting_System.md`](Blob_Hunting_System.md) 6-4절)

### 11-3. 드랍 규칙

| 항목 | 규칙 |
|---|---|
| 드랍 풀 | **도감에 해금된 것만** 나온다 |
| 요구 레벨 | 각성 레벨에 미달하는 인자는 주울 수는 있으나 **끼울 수 없다** |
| 첫 Core | 레이드 시작 직후 **부여 계열 Core 1개를 확정 드랍**한다 |
| 고유(보스) | **확정 드랍 1개** |
| 중복 | 허용한다. 같은 인자를 두 개 주울 수 있다 (두 Core에 하나씩 끼운다) |

> **첫 Core 확정 드랍이 없으면 안 된다.** 인자가 하나도 없으면 아무것도 쏘지 못한다.
> 그리고 부여 계열이어야 한다 — 기폭 계열만 있으면 `투사체` 태그를 가진 Core가 없어
> 투사체 Support 12종이 통째로 죽는다.

## 12. 소켓 규칙

| 항목 | 규칙 |
|---|---|
| Core 보유 상한 | 2개 |
| Core당 소켓 | 3개 (최대 6 Support) |
| Meta 동시 장착 | 2개 |
| 전령 동시 장착 | 1개 |
| **소켓 개방** | **각성 레벨이 연다** (12-1절) |
| **장착 시점** | 인자를 주운 뒤 **언제든** |
| **소켓 탈착** | **가능.** 이미 낀 인자를 빼서 다른 것으로 갈아끼울 수 있다 |
| 탈착한 인자 | 가방으로 돌아간다. 버리지 않는다 |
| 태그 게이팅 | 그대로. 요구 태그를 만족하는 Core에만 끼워진다 |
| 상호 배타 | 그대로. 동시 장착 시 양쪽 무효화 |
| Nucleus | 도입하지 않는다 |

> **소켓 탈착을 허용한 이유** — 인자가 실물 아이템이 되면서
> "끼웠다가 빼면 사라진다"는 규칙은 아이템을 파괴하는 것이라 납득되지 않는다.
> 장비를 갈아입는 것과 같은 조작이어야 한다.
> 결정의 무게는 **무엇을 주웠는가**와 **무엇을 들고 나가는가**가 대신 진다.

### 12-1. 각성 레벨 = 소켓 개방

각성 레벨은 그대로 유지된다. 보상만 바뀐다.

| 각성 레벨 | 개방 |
|---|---|
| 1 | Core 1 + 소켓 1 |
| 3 | 소켓 2 |
| 5 | 소켓 3 |
| **7** | **Core 2 + 소켓 1** (기존 확정 사항 유지) |
| 9 | 소켓 2 |
| 11 | 소켓 3 + **발동 1** |
| 13 | **발동 2** |
| 15 | **전령 1** |

- 레벨업 순간에 선택창이 뜨지 않는다. **소켓이 하나 열릴 뿐이다.**
- 인자를 미리 주워 뒀다면 열리는 즉시 끼울 수 있다.
- 경험치는 시체를 흡수해 얻는다. (Biomass라는 이름은 폐기했다 — 3절 참조)

> 소켓 개방이 레벨 보상이 되면 **"주웠는데 끼울 데가 없다"**는 압박이 생긴다.
> 이것이 레벨업을 계속 원하게 만드는 동력이며, 이전의 "선택창이 열린다"를 대체한다.

### 12-2. 영구 성장 3축

1. **도감** — 무엇이 나올 수 있는가
2. **창고** — 실제로 가진 인자와 장비 (죽으면 들고 나간 만큼 잃는다)
3. **계정 레벨** — 가방 공간 · 최대 체력 · 감각

## 14. 절대 금지 사항

1. 단순 스탯 증가만 주는 Skill을 만들지 않는다.
   상시 능력치는 전부 장비가 담당한다. Skill은 메커니즘만 바꾼다.
2. 다양성을 "중복 획득 금지"로 강제하지 않는다.
3. 확률 발동 트리거를 쓰지 않는다. 에너지 축적형을 쓴다.
4. 대가로 직접 피해 수치 감소를 쓰지 않는다.
5. 티어(I/II/III) 체계를 도입하지 않는다. 모든 Skill은 단일 정의다.
   ※ 장비는 티어를 쓴다. 서로 다른 아이템이므로 문제가 없다.
6. 소환수 계열을 도입하지 않는다.
7. 정지(stationary)를 보상하는 Skill을 만들지 않는다.
8. Skill에 상태이상 면역이나 해제를 두지 않는다.
   거는 것은 Skill, 막는 것은 장비다. 한쪽이 둘 다 하면 장비가 무의미해진다.
9. Skill에 방어도나 방어 관통을 두지 않는다.
   단단한 적을 뚫는 답은 【장비 = 방어 관통】과 【Skill = 속성·상태이상】
   두 가지이며, 서로를 대체하면 성장 축 하나가 죽는다.

## 15. 조합 예시

① 「밀집 서식」 — 전이 특화 (적재 7)
   화염 / 원소 작렬 / 불난 집 부채질 / 파편 탄환 / 갈래 / 짧은 퓨즈 / 재의 전령
   작동 : 파편 탄환이 날아가며 3갈래로 갈라지고, 각 파편이 적중 시 갈래로
          또 2갈래가 되어 점화를 넓게 뿌린다
   트리거 : 점화된 적이 사망하는 시점
   결과 : 재의 전령이 점화 폭발로 주변을 다시 점화시키고, 원소 작렬이 남은
          점화를 소모해 화염 잔류물을 깐다 → 무리 하나가 통째로 연쇄 소멸

② 「산개 순찰」 — 단일 화력 특화 (적재 6)
   열상 / 유혈 충동 / 깊은 상처 / 관통 / 부메랑 / 원거리 사격
   작동 : 관통탄이 일렬로 출혈을 걸고, 부메랑으로 같은 대상을 두 번 때린다
          유혈 충동은 출혈을 만들지 못하므로 열상이 필수다
   결과 : 개별 조우를 원거리에서 빠르게 정리한다
   ※ 전령을 넣지 않는다. 적이 흩어져 있어 처치 연쇄가 이어지지 않는다

※ 나머지 조합 예시는 git 히스토리(Skill_System.md)를 참조한다.

## 16. 데이터화

- Skill은 반드시 ScriptableObject로 정의한다. 코드 하드코딩 금지.
  위치: Assets/Data/ScriptableObjects/Skills/
- SkillTag는 [System.Flags] enum. 비트 연산 1회로 끝나야 한다.
- 선택 풀 필터는 MonoBehaviour 의존 없는 순수 클래스로 분리한다.
- 정의 에셋은 Resources 밖에 두고, Resources/SkillCatalog.asset 하나가
  목록을 들고 있다. SkillCatalogBuilder가 임포트 시점에 폴더를 스캔해
  자동 갱신하므로 Inspector 드래그를 잊는 실패 지점이 없다.
- SkillDefinition에는 상시 능력치 필드를 두지 않는다.
  이동 속도·시야·흡수 범위는 전부 EquipmentDefinition의 몫이다.
