1. 명명 원칙
--------------------------------------------------------------------------------
1. poe2db 한글판의 실존 젬명을 그대로 쓴다.
2. 이름이 같은 젬이 없으면 효과가 가장 가까운 실존 젬의 이름을 차용한다.
3. 실존 젬에 대응 메커니즘 자체가 없으면, poe2db의 명명 관례(짧은 기계적 명사,
   「투사체 ○○」 계열)에 맞춰 짓고 그 사실을 문서에 명시한다.

   ※ v6는 3항을 "기능째 삭제"로 두었으나, 삭제하면 충돌 우선순위 큐의 담당이
      비는 부작용이 컸다. v7에서 "관례에 맞춰 신조"로 완화했다.

예외 — 스킬이 아니므로 이 원칙의 대상이 아니다.
   변이체(Mutant) / 변이 샘플 / 장비 아이템명

--------------------------------------------------------------------------------
반드시 Core 소켓에 장착된다. 전역 버프가 아니다.

[6-1. 통화(Cost) — 7종]
직접 피해 수치 감소는 사용하지 않는다.
체력 10 / 짧은 TTK 환경에서 유저는 DPS 변화를 인지하지 못한다.

  · 탄막 밀도    : 발사 간격 증가, 탄 수 감소
  · 유효 사거리  : 사거리·범위 축소 → 접근 강요 → 위험 증가
  · 조작 제약    : 행동 자체를 제약
  · 기능 배타    : "X를 이용하는 대신 X를 생성할 수 없다"
  · 투사체 속도  : 탄속 증감
  · 지속시간     : 상태이상·잔류물의 지속시간 증감
  · 즉시성       : 발동 지연, 즉발 → 지속 전환

  ※ CostType enum에 Damage 항목을 두지 않는다.
     금지 대상은 【직접 피해 수치 감소】(예: 피해 -20%)에 한정한다.

9. 충돌 우선순위 큐
--------------------------------------------------------------------------------

        Split  →  Pierce  →  Fork  →  Chain  →  Return

한 번의 충돌에는 단 하나만 해결된다.

| 단계   | 담당        | 기본값                          |
|--------|-------------|---------------------------------|
| Split  | 파편 탄환   | 3갈래. 파편은 재분열하지 않는다 |
| Pierce | 관통        | 3체                             |
| Fork   | 갈래        | 2갈래, 원 궤도 기준 ±60도       |
| Chain  | 연쇄        | 3회, 동일 적 재타격 불가        |
| Return | 투사체 회수 | 1회. 재타격이 허용되는 유일한 예외 |

  ★ v7에서 5단계 담당이 전부 채워졌다. v6는 Pierce·Chain 2개뿐이었다.

[큐에 들어가지 않는 것]
  튕겨 쏘기      : 지형 충돌에서 발동. 적 충돌 큐를 소모하지 않는다
  다중 사격      : 발사 시점에 탄이 늘어난다. 충돌과 무관하다
  추격           : 지속 유도(호밍). 충돌 시 재유도가 아니다
  투사체 가속/감속: 속도 변경일 뿐 충돌 판정이 아니다
  폭발 투사체    : 적중 지점에서 새 투사체를 만든다. 큐를 소모하지 않는다
  원거리 사격    : 거리 조건 효과

  → 이들을 큐에 넣으면 관통과 서로를 막게 되어 설계 의도가 깨진다.

[배타가 자동 발생하는 구조]
  관통과 갈래를 둘 다 보유하면 한 충돌에서 관통만 해결되고 갈래는 발동하지 않는다.
  곱연산이 일어나지 않는다. 수치 인플레 없이 선택의 무게가 생긴다.

10. 합성 발사 (Composite Fire)
--------------------------------------------------------------------------------
Core를 2개 보유해도 따로 발사하지 않는다. 한 발에 합쳐진다.

  부여 계열 Core → 그 탄이 부여할 상태 (점화 / 중독 / 동결 / 감전 / 출혈)
  소켓의 Support → 그 탄의 투사체 행동 (관통 / 연쇄 / 갈래 / 파편 탄환 / …)
  기폭 계열 Core → 투사체가 아니므로 합성 대상이 아니다. 독립 발동한다.

  예: 화염 Core + 소켓의 관통 = "관통하면서 점화시키는 탄 1발"

[채택 근거]
| 방식       | 탄 수 | 문제                                        |
|------------|-------|---------------------------------------------|
| 동시 발사  | 2배   | 모바일에서 발열·드로우콜 부담이 가장 크다   |
| 교대 발사  | 1배   | 상태 부여 빈도 절반 → 부여 Core 체감 붕괴   |
| 주·보조 전환| 1배  | 전환 버튼이 하나 더 필요하다                |
| **합성**   | 1배   | —                                           |

[확정 규칙]
1. Core 개수는 탄 수에 영향을 주지 않는다. 탄이 늘어나는 것은 「다중 사격」뿐이다.
2. 부여 Core가 2개면 발사마다 번갈아 부여한다.
   동시 부여로 만들면 「원소 융합」(대가: 적용 빈도 절반)이 무가치해진다.
   번갈아 부여하면 각 상태가 정확히 50% 빈도가 되어 원소 융합과 같은 수준이 된다.
     - Core 2개 방식 : Core 슬롯을 쓴다 (대신 소켓 3개가 딸려온다)
     - 원소 융합 방식 : 소켓 1칸을 쓴다 (대신 Core 슬롯을 지킬 수 있다)
3. 기능 배타로 차단된 상태(번제 → 점화)는 탄에 실리지 않는다.
4. 태그 게이팅은 Core 단위를 유지한다.

[2번째 Core 슬롯]
  Lv7에 열린다. "Core 보유 상한 2개"는 상한이지 즉시 지급 보장이 아니다.
  초반에는 메커니즘 하나만 익히게 하고, 단일 Core 빌드를 완성한 뒤 확장한다.

     투사체 Support 12종이 통째로 죽는다. 그래서 "부여 Core 최소 1개"다.

  이탈 방지 안전장치로도 기능한다. Duckov의 개(dog) 슬롯과 같은 역할이다.

13. 레이드 특성 — 10
--------------------------------------------------------------------------------
한 레이드에 1~2개가 부여되며 진입 전에 공개된다.

| 특성      | 내용                    | 유리                      | 불리          |
|-----------|-------------------------|---------------------------|---------------|
| 밀집 서식 | 적이 무리로 뭉쳐 있음   | 전이 · 확산 · 범위        | 단일 집중     |
| 산개 순찰 | 적이 넓게 흩어짐        | 단일 화력 · 기동 · 관통   | 전이 · 연쇄   |
| 경화 외피 | 적 방어도 높음          | 관통 · 즉발 화력          | 지속 피해     |
| 재생 조직 | 적이 체력 회복          | 즉발 화력                 | 점화 · 중독   |
| 내화 피부 | 화염 저항 높음          | —                         | 화염 봉인     |
| 저온 적응 | 냉기 저항 높음          | —                         | 서리 봉인     |
| 절연 피막 | 번개 저항 높음          | —                         | 뇌전 봉인     |
| 면역 항체 | 카오스 저항 높음        | —                         | 역병 봉인     |
| 응고 혈액 | 출혈 지속 절반          | —                         | 열상 봉인     |
| 부식 대기 | Biomass 흡수량 감소     | 저레벨 완성형 빌드        | 후반 스케일   |

  ※ 속성 봉인은 5속성 전부에 존재해야 한다.
     일부만 봉인하면 봉인되지 않는 속성이 곧 "모든 레이드를 도는 그 하나"가 된다.
  ※ 밀집 서식과 산개 순찰은 동시에 부여되지 않는다.
  ※ 전령 삭제로 「밀집 서식」의 유리 항목에서 전령이 빠졌다.

15. 절대 금지 사항
--------------------------------------------------------------------------------
1. 단순 스탯 증가만 주는 Skill을 만들지 않는다.
   ※ 상시 능력치는 전부 장비가 담당한다. Skill은 메커니즘만 바꾼다.
      유지형 폐지로 이 원칙의 예외가 사라졌다.
2. 다양성을 "중복 획득 금지"로 강제하지 않는다.
3. 확률 발동 트리거를 쓰지 않는다. 에너지 축적형을 쓴다.
4. 대가로 직접 피해 수치 감소를 쓰지 않는다. (예: 피해 -20%)
5. 티어(I/II/III) 체계를 도입하지 않는다. 모든 Skill은 단일 정의다.
6. 소환수 계열(드론/포탑/포자 등 독립 개체)을 도입하지 않는다.
7. 정지(stationary)를 보상하는 Skill을 만들지 않는다.

16. 조합 예시
--------------------------------------------------------------------------------

① 「밀집 서식」 — 전이 특화 (적재 6)
   화염 / 원소 작렬 / 불난 집 부채질 / 파편 탄환 / 갈래 / 짧은 퓨즈
   작동 : 파편 탄환이 날아가며 3갈래로 갈라지고, 각 파편이 적중 시 갈래로
          또 2갈래가 되어 점화를 넓게 뿌린다
   트리거 : 점화된 적이 사망하는 시점
   결과 : 원소 작렬이 점화를 소모해 화염 잔류물을 깔고, 짧은 퓨즈가 지연을
          없애 즉시 연쇄한다 → 무리 하나가 통째로 연쇄 소멸

② 「산개 순찰」 — 단일 화력 특화 (적재 6)
   열상 / 유혈 충동 / 깊은 상처 / 관통 / 투사체 회수 / 원거리 사격
   작동 : 관통탄이 일렬로 출혈을 걸고, 투사체 회수로 같은 대상을 두 번 때린다
   유혈 충동은 출혈을 만들지 못하므로 열상이 필수다
   결과 : 개별 조우를 원거리에서 빠르게 정리한다

③ 「경화 외피」 — 관통 · 증폭 특화 (적재 7, 슬롯 확장 후)
   뇌전 / 감전 도약 / 넘치는 충전 / 관통 / 감전 시 시전 / 치명타 시 시전 / 기세
   작동 : 관통탄이 일렬로 감전을 걸어 받는 피해를 35%까지 증폭시킨다
   트리거 : 감전 유발 누적으로 「감전 시 시전」 에너지 100% 도달
   결과 : 화면 내 감전된 모든 적에게 낙뢰 → 방어도가 높아 지속 피해가
          통하지 않는 적을 증폭 + 즉발로 공략

④ 「저온 적응」 — 속성 조율 공략 (적재 7)
   서리 / 화염 조율 / 원소 작렬 / 긴 퓨즈 / 관통 / 지속시간 연장 / 원소 상태 이상 시 시전
   작동 : 완성된 서리 빌드를 그대로 가져가되 화염 조율로 냉기를 화염으로 전환한다
   결과 : 동결 기반이 점화 기반으로 전환되고, 긴 퓨즈가 누적 점화를 한 번에
          소모한다 → 봉인된 속성을 우회

⑤ 「재생 조직」 — 즉발 화력 특화 (적재 7)
   서리 / 얼어붙은 악의 / 살을 에는 서리 / 원소 작렬 / 짧은 퓨즈 / 지속시간 압축 / 충격파
   작동 : 지속 피해가 재생에 상쇄되므로 동결로 행동을 봉쇄하고 즉발로 처리한다
   살을 에는 서리가 동결을 소모하고, 얼어붙은 악의가 다시 공급한다
   결과 : 재생할 틈을 주지 않는 즉발 루프

17. 데이터화
--------------------------------------------------------------------------------
- Skill은 반드시 ScriptableObject로 정의한다. 코드 하드코딩 금지.
  위치: Assets/Data/ScriptableObjects/Skills/
- SkillTag는 [System.Flags] enum. 선택창을 열 때마다 전체 풀을 필터링하므로
  비트 연산 1회로 끝나야 한다. 문자열 리스트 비교 금지.
- 선택 풀 필터는 MonoBehaviour 의존 없는 순수 클래스로 분리한다.
- 정의 에셋은 Resources 밖에 두고, Resources/SkillCatalog.asset 하나가
  목록을 들고 있다. SkillCatalogBuilder가 임포트 시점에 폴더를 스캔해
  자동 갱신하므로 Inspector 드래그를 잊는 실패 지점이 없다.
