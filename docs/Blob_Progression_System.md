# Progression System

> **담당** — 무엇이 남는지 정한다 · 왜 다시 들어가는가
> 서사·단서는 [`Story.md`](Blob_Story.md), 구조와 규칙만 여기서 정한다.

```
장(어디로) → 해금(무엇이 열리고) → 계정 레벨(무엇이 남고)
           → 의뢰(무엇을 하라고 시키고) → 레코더(무엇을 알려주는가)
```

---

## 1. 두 개의 레벨

| 축 | 이름 | 재화 | 주는 것 | 초기화 |
|---|---|---|---|---|
| 출격 내 | **각성 레벨** | 경험치 (즉시) | **소켓 개방** | 출격 종료 시 |
| 출격 간 | **계정 레벨** | 추출 성공 시 정산 | **해금 포인트 1** | 영구 |

> ⚠️ 두 이름을 반드시 구분한다. 한쪽을 그냥 "레벨"이라 부르면 UI와 세이브가 뒤엉킨다.

- **각성 레벨** — 레벨업 시 소켓이 하나 열린다. **선택창은 뜨지 않는다.** 경험치는 시체 흡수로 얻는다. 개방 표 → [`Skill_System.md`](Blob_Skill_System.md) 12-1절
- **계정 레벨** — **추출에 성공해야만** 정산된다. 실패하면 그 출격의 계정 경험치는 0.

> 소켓 개방이 레벨 보상이면 "주웠는데 끼울 데가 없다"는 압박이 생긴다. 이것이 레벨업을 계속 원하게 만드는 동력이다.

## 2. 해금 트리 → 패시브로 일원화했다

**별도의 해금 트리를 두지 않는다.** 계정 축의 성장은 전부 패시브 하나다.
→ [`Blob_Passive_System.md`](Blob_Passive_System.md) · 요약은 아래 8절

> 이전에는 이 자리에 「가방 확장 / 조직 강화 / 시야 확장 / 흡수 범위 / 시체 회수」
> 7계열 표가 있었다. 그런데 **패시브 5계열과 5개 축에서 정면으로 겹쳤고**,
> 코드는 패시브만 구현했다. 축을 둘로 두면 유저가 무엇이 무엇인지 외워야 한다.
> (`docs/Blob_Audit.md` B1)

**금지**

- 패시브에 투사체 행동이나 상태이상 부여를 두지 않는다 (젬의 몫)
- 패시브에 전투 수치를 두지 않는다 — **체력·시야·감지도 포함한다** (장비의 몫)
- **실시간 대기(연구·건설 시간)를 두지 않는다.** 비용은 재료와 크레딧으로만 받는다

## 3. 장(Stage) 구조 — 선형 해금 + 자유 재방문

난이도가 고정된 장을 **골라 들어간다.** 순차로 밀고 나가는 방식이 아니다.

```
[지상 문] ── 6장  센트럴 바이오 돔
             5장  메인프레임 서버실
             4장  특수 격리 및 위험물 실험동
             3장  메디컬 & 정제 연구동
             2장  수로 및 동력 제어 구역
[은신처] ── 1장  지하 폐기물 처리장
```

각 장의 테마·적·파밍·단서 → [`Story.md` 2절](Blob_Story.md)

### 문턱 4종

| 종류 | 내용 |
|---|---|
| 물리 진입 | 처음에는 이전 장을 통해서만 진입 (일방통행) |
| **표식** | 한 번 다녀오면 은신처에서 직행 |
| 인증 | 5장은 4장 보스의 소모성 인증 코드 필요 |
| 환경 장비 | 3장 소독 / 4장 오염 경보 / 6장 지상 포자 |

> **표식이 핵심이다.** "스테이지 진행"이 아니라 **"오늘 어디를 털지 고른다"**가 된다.

**숏컷과 역주행** — 상위 장의 키 카드로 하위 장의 비밀 통로(고티어 파밍 구역)를 연다. 맵 제작비를 절약하면서 전 장에 재방문 가치를 준다.

> 장이 바뀌어도 적 수치에 배율을 곱하지 않는다. 바뀌는 것은 **구성비와 무장 티어**다. → [`Combat_Baseline.md` 8절](Blob_Combat_Baseline.md)

## 4. 의뢰(Contract) — 해금의 배달부

상점은 처음부터 열려 있지 않다. **의뢰가 한 줄씩 연다.**

| 유형 | 예 | 역할 |
|---|---|---|
| 반출형 | 특정 재료 N개 반출 | 파밍 목표 |
| 처치형 | 지정 등급·유형 N마리 | 전투 숙련 |
| **조건부 처치형** | **지정 스킬로 / 정전 중에 / 침수 상태에서** | ★ |
| 도달형 | 특정 지점 도달 후 추출 | 탐험 유도 |
| 상호작용형 | 장치 수리·설치 | 동선 설계 |
| 선행 준비형 | 특정 도구를 들고 출격 | 출격 전 계획 강제 |

**조건부 처치형이 가장 중요하다.** 숙련 유도 + 플레이 다양화 + 재화 싱크 + 시설 상태 활용을 한 번에 해결한다. 모바일에서 비용 대비 효율이 가장 높다.

**보상** — 계정 경험치 + 재화 + 아이템 + **해금**(상인 재고 한 줄 / 제작법 / 장 표식)

**동선 유도는 좌표가 아니라 랜드마크 문장으로 한다.** 구역 단위 하이라이트까지만 허용하고 핀포인트 마커는 두지 않는다 — 보스와 갑자기 마주치는 긴장을 없애기 때문이다.

**상인** — NPC마다 담당 해금 축이 다르고, **NPC 영입 자체가 의뢰다** (설비 수리 → 연락 → 건설 → 입주). 3장에서 상인들이 실험의 장본인임이 밝혀진 뒤 **계속 거래 / 단절**을 고를 수 있다. 단절하면 그 해금 라인이 막히는 대신 다른 보상이 열린다.

## 5. 레코더 — 수집형 로어

하나의 아이템이 네 역할을 겸한다. **별도 튜토리얼 UI가 필요 없어 개발 비용이 오히려 줄어든다.**

1. 튜토리얼 대체 — "붉은 빛이 번뜩이면 그때 구르면 된다"
2. 공략 힌트 — "하얀 것을 보면 건드리지 마라"
3. 약점표 — "정착체는 불에 약하다"
4. 서브시스템 DB — 시설 상태별 스폰표를 여러 장에 나눠 배포

- 배치는 진행 순서와 일치시킨다 (1장 레코더는 1장에만)
- 일부는 **훼손된 상태**로 제시해 수집 욕구를 만든다
- **소량 보상(재화)을 붙인다.** 모바일 유저는 순수 로어만으로 수집하지 않는다
- **레코더가 스토리의 유일한 전달 수단이다.** 컷신을 쓰지 않는다

## 6. 추출과 사망 페널티

| 구분 | 추출 성공 | 추출 실패 |
|---|---|---|
| 무기 · 방어구 · 가방 | 유지 | **소실** |
| **젬(스킬)** | 창고로 | **소실** |
| 미등록 변이 샘플 | 도감에 영구 등록 | **소실** |
| 계정 경험치 | 정산 | **0** |
| **각인** | 유지 | **유지** |
| 도감 · 계정 레벨 | 유지 | 유지 |

> 유저가 배울 규칙은 하나다 — **죽으면 들고 있던 것 전부.**
> 단, **도감은 「해금 기록」**이라 남는다. 무엇이 나올 수 있는지는 기억하지만 실물은 매번 다시 구한다.

**영구 진행 레이어는 도감 + 계정 레벨 + 각인 3가지다.** 전부 잃어도 맨몸으로 다시 시작할 수 있게 하는 안전망이다.

**시체 회수** — 「시체 회수 I」 해금 시 추출 실패한 시체를 **단 한 번** 되찾으러 갈 수 있다. 되찾으러 가다 다시 죽으면 이전 시체는 사라진다. → "복구할까, 포기할까"라는 두 번째 추출 판단이 생긴다.

## 7. 세션 길이 (모바일 제약)

- 1회 레이드 목표 **8~15분**
- 하드 타이머 없음. 압박은 시설 상태와 무게에서 온다
- **은신처 체류는 3분 이내에 끝날 수 있어야 한다** → 실시간 대기 금지(2절), 창고 검색·정렬 필수

## 8. 패시브 (계정 축)

상세 → [`Blob_Passive_System.md`](Blob_Passive_System.md)

- 계열 5개 — 적응 / 대사 / 회수 / 중개 / 역행
- 해금 조건 3종 — 계정 레벨 / 크레딧만(중개) / **조우(역행)**
- 크레딧 외에 **필요물품(아이템)** 을 요구한다
- **패시브는 전투 수치를 주지 않는다.** 방어도·피해·체력·이동·시야·감지는 전부 장비다

| 축 | 여는 것 | 잃는가 |
|---|---|---|
| 각성 레벨 | 소켓 | 런마다 초기화 |
| 장비 · 젬 | 전투 능력 | 죽으면 들고 있던 것 전부 |
| 계정 레벨(패시브) | 휴대 · 수집 · 회수 · 경제 · 해금 | 영구 |

## 9. 업적과 엔딩

**업적 6분류** — 도달(각 장 첫 도착 6개) / 건설(NPC 입주 연동) / 처치(보스별 1회·10회) / 축적(크레딧 1만·10만·100만) / 해금(패시브 정점·작업대 Ⅳ·도감 완성) / 엔딩

**끝을 하나로 두지 않는다.** 마지막에 무엇을 아는 상태로 도달했는지가 갈림을 만든다.

| 엔딩 | 조건 | 뜻 |
|---|---|---|
| **탈출** | 6장 클리어 | 나온다. 아무것도 모른 채 |
| **귀환** | 레코더 전부 수집 후 클리어 | 무엇이 있었는지 알고 나온다 |
| **잔류** | 도감 완성 후 클리어 | 나가지 않기로 한다 |
| **역행** | 역행 계열 해금 후 클리어 | → [`Passive_System.md`](Blob_Passive_System.md) 1절 |
| **배드** | 단서 부족 상태로 문을 연다 | 지상 포자를 추리하지 못해 사망 |

> 엔딩의 정본은 [`Story.md` 3절](Blob_Story.md)이다. 조건이 어긋나면 그쪽을 따른다.

레코더·도감·패시브가 각각 하나씩 엔딩에 닿는다. 수집 요소가 장식이 아니라 결말의 조건이 된다.

**「재능」 축은 도입하지 않는다.** 이미 축이 넷이다(장비·젬·각인·패시브). 다섯 번째를 넣으면 어느 축을 올릴지가 아니라 무엇이 무엇인지를 외우는 게임이 된다.
