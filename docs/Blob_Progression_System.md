# Progression System

> **담당** — 무엇이 남는지 정한다 · 왜 다시 들어가는가
> **근거** — Escape from Duckov 구역 / 퀘스트 / 스킬 / 노트 / 모드 ([`research/`](research/))
> 장의 서사·단서는 [`Story.md`](Blob_Story.md)에 있다. 이 문서는 **구조와 규칙**만 정한다.

```
장(어디로) → 해금(무엇이 열리고) → 계정 레벨(무엇이 남고)
           → 의뢰(무엇을 하라고 시키고) → 레코더(무엇을 알려주는가)
```

Skill이 "한 판 안에서의 성장", 장비가 "판과 판 사이의 성장"이라면 진행은 **"게임 전체의 성장"**이다.

## 1. 두 개의 레벨 — Blob의 뼈대

덕코프의 레벨은 런 중 보상이 아니라 **거점 영구 해금 트리의 레벨**이다. [확인됨]
반면 "레벨업 → 스킬 선택"은 PoE2/로그라이트 차용이다. 서로 다른 축이므로 **함께 둔다.**

| 축 | 이름 | 재화 | 주는 것 | 초기화 |
|---|---|---|---|---|
| 런 내 | **각성 레벨** | 경험치 (즉시) | **소켓 개방** | 런 종료 시 |
| 런 간 | **계정 레벨** | 추출 성공 시 정산 | **해금 트리 포인트** | 영구 |

> ⚠️ 두 레벨의 이름을 반드시 구분한다. 한쪽을 그냥 "레벨"이라 부르지 않는다. 겹치면 UI와 세이브가 즉시 뒤엉킨다.

- **각성 레벨** — 레벨업 시 **소켓이 하나 열린다.** 선택창은 뜨지 않는다. 2번째 Core 슬롯은 Lv7. 레벨 자체는 런이 끝나면 초기화된다.
  경험치는 시체를 흡수해 얻는다. (이전 명칭 「Biomass」는 폐기했다 — 그냥 **경험치**다)
- **계정 레벨** — **추출에 성공해야만** 정산된다. 실패하면 그 런의 계정 경험치는 0이다. 레벨업 1회당 해금 포인트 1.

> **소켓 개방이 레벨 보상이 되면** "주웠는데 끼울 데가 없다"는 압박이 생긴다.
> 이것이 레벨업을 계속 원하게 만드는 동력이며, 이전의 "선택창이 열린다"를 대체한다.
> 개방 표는 [`Skill_System.md`](Blob_Skill_System.md) 12-1절.

## 2. 해금 트리

덕코프 스킬 트리를 도용하되 낚시·수분·에너지 같은 생존 시뮬 계열은 뺀다. 모바일 세션이 짧아 관리 부담을 늘리는 축을 도입하지 않는다.

| 계열 | 노드 | 효과 | 선행 |
|---|---|---|---|
| **운반** | 가방 확장 I~V | **적재 공간 +3** | 순차 |
| 운반 | 소지 확장 I~III | 최대 소지 중량 +5 | 가방 I |
| 생체 | 조직 강화 I~IV | 최대 체력 +5 / +5 / +10 / +10 | 가방 I |
| 감각 | 시야 확장 I~II | 시야 각도 +15 | 가방 I |
| 흡수 | 흡수 범위 I~III | 경험치 흡수 범위 +20% | 생체 I |
| 흡수 | 흡수 효율 I~II | 각성 경험치 +10% | 흡수 I |
| 회수 | 시체 회수 I | 추출 실패 시 시체를 **1회** 되찾을 수 있다 | 계정 Lv10 |

**「적재 확장」은 폐기하고 「가방 확장」으로 통합했다.**
인자가 실물 아이템이 되어 장비·전리품과 같은 인벤토리를 쓰기 때문이다.
가방이 커지면 인자도 전리품도 더 들고 갈 수 있다 — 한 축이 두 가지를 동시에 보상한다.

**최대 체력은 장비 전용이 아니다.** 덕코프도 트리로 소폭 올린다. [확인됨]
기본 100 + 트리 30 + 장비 50 = 상한 180.

**금지**
- 트리에 투사체 행동이나 상태이상 부여를 두지 않는다. 스킬의 몫이다.
- **실시간 대기(연구 시간, 건설 시간)를 두지 않는다.** 덕코프 최대 페인 포인트 중 하나이며(모드 「Instant Building Upgrade」), 모바일에서는 이탈로 직결된다. 비용은 재료와 포인트로만 받는다.

## 3. 장(Stage) 구조 — 선형 해금 + 자유 재방문

스테이지를 순차로 밀고 나가는 방식이 아니라 **난이도가 고정된 장을 골라 들어가는** 방식이다. [확인됨]

```
[지상 문] ── 6장  센트럴 바이오 돔
                  │
             5장  메인프레임 서버실
                  │
             4장  특수 격리 및 위험물 실험동
                  │
             3장  메디컬 & 정제 연구동
                  │
             2장  수로 및 동력 제어 구역
                  │
[은신처] ── 1장  지하 폐기물 처리장
```

각 장의 테마·적·파밍·단서는 [`Story.md` 2절](Blob_Story.md).

### 게이트 4종

| 종류 | 내용 |
|---|---|
| **물리 진입** | 처음에는 이전 장을 통해서만 들어갈 수 있다 (일방통행) |
| **표식** | 한 번 다녀오면 은신처에서 직행할 수 있다 |
| **인증** | 5장은 4장 보스가 떨구는 소모성 인증 코드가 필요하다 |
| **환경 장비** | 3장 소독 / 4장 오염 경보 / 6장 지상 포자 |

> **표식이 핵심이다.** 한 번 뚫으면 되돌아갈 수 있으므로 "스테이지 진행"이 아니라 **"오늘 어디를 털지 고른다"**가 된다. 추출 게임의 핵심 결정이 여기서 나온다.

### 숏컷과 역주행

상위 장에서 얻은 키 카드로 **하위 장의 비밀 통로(고티어 파밍 구역)**를 연다.
전 장을 다시 탐험할 가치가 생기고, 장을 재활용하므로 맵 제작비가 절약된다.

> 장이 바뀌어도 적 수치에 배율을 곱하지 않는다. 바뀌는 것은 **구성비와 무장 티어**다. → [`Combat_Baseline.md` 8절](Blob_Combat_Baseline.md)

## 4. 의뢰(Contract) — 해금의 배달부

덕코프의 퀘스트는 단순 목표가 아니라 **기능 해금 트리 그 자체**다. 상점은 처음부터 열려 있지 않고 퀘스트로 한 줄씩 열린다. [확인됨] 이 구조를 그대로 도용한다.

| 유형 | 예 | 설계 역할 |
|---|---|---|
| 반출형 | 특정 재료 N개를 은신처로 | 파밍 목표 |
| 처치형 | 지정 등급·원형을 N마리 | 전투 숙련 |
| **조건부 처치형** | **지정 스킬로 / 정전 중에 / 침수 상태에서** | ★ 아래 |
| 도달형 | 특정 지점 도달 후 추출 | 탐험 유도 |
| 상호작용형 | 장치를 수리·설치 | 동선 설계 |
| 선행 준비형 | 특정 도구를 들고 출격 | 출격 전 계획 강제 |

**조건부 처치형이 가장 중요하다.** "정전 중에만 나오는 데이터체 3마리", "부여 Core 없이 고유 등급 처치" 같은 의뢰가 **숙련 유도 + 플레이 다양화 + 재화 싱크 + 시설 상태 활용**을 한 번에 해결한다. 모바일에서 가장 비용 대비 효율이 높은 콘텐츠다.

**보상 구성** — 계정 경험치 + 재화 + 아이템 + **해금**(상인 재고 한 줄 / 제작법 / 장 표식)

**동선 유도는 좌표가 아니라 랜드마크 문장으로 한다.**
> 덕코프 모드 문서가 직접 경고한다 — 퀘스트 위치를 지도에 핀으로 찍으면 "갑작스럽게 보스와 마주치는 긴장감이 없어진다". [확인됨]
> 모바일 가독성을 위해 **구역 단위 하이라이트**까지만 허용한다. 핀포인트 마커는 두지 않는다.

### 상인

NPC마다 담당 해금 축이 다르다. **NPC 영입 자체가 의뢰다.** (설비 수리 → 연락 → 건물 건설 → 입주)

> 3장에서 **상인들이 실험의 장본인**임이 밝혀진다. 이후 상인별로 **계속 거래 / 단절**을 고를 수 있고, 단절하면 그 해금 라인이 막히는 대신 다른 보상이 열린다. → [`Story.md`](Blob_Story.md)

## 5. 레코더 — 수집형 로어의 4중 역할

덕코프의 「노트」 65개는 네 가지 기능을 겸한다. [확인됨] 같은 구조로 만든다. **별도 튜토리얼 UI가 필요 없어 개발 비용이 오히려 줄어든다.**

1. **튜토리얼 대체** — "붉은 빛이 번뜩이면 그때 구르면 된다"
2. **공략 힌트** — "하얀 것을 보면 건드리지 마라"
3. **약점표** — "정착체는 불에 약하다"
4. **서브시스템 DB** — 시설 상태별 스폰표를 여러 장에 나눠 배포

- 배치는 진행 순서와 일치시킨다. 1장 레코더는 1장에만 있다.
- 일부는 **내용이 훼손된 상태**로 제시해 수집 욕구를 만든다.
- 덕코프는 노트에 보상을 붙이지 않았다. **Blob은 소량 보상(재화)을 붙인다.** 모바일 유저는 순수 로어만으로 수집하지 않는다.
- **레코더가 스토리의 유일한 전달 수단이다.** 컷신을 쓰지 않는다. → [`Story.md`](Blob_Story.md)

## 6. 추출과 사망 페널티

| 구분 | 추출 성공 | 추출 실패 |
|---|---|---|
| 무기 · 방어구 · 가방 | 유지 | **소실** |
| **인자(스킬)** | **창고로 간다** | **소실** |
| 미등록 변이 샘플 | 도감에 영구 등록 | **소실** |
| 계정 경험치 | 정산 | **0** |
| **각인** | 유지 | **유지** |
| **도감(해금 기록)** · 계정 레벨 | 유지 | 유지 |

> **인자도 죽으면 잃는다.** 장비와 같은 규칙이므로 유저가 배울 것은 하나다 — **죽으면 들고 있던 것 전부.**
> 반면 **도감은 「해금 기록」**이라 남는다. 무엇이 나올 수 있는지는 기억하지만
> 실물은 매번 다시 구해야 한다. (덕코프의 설계도와 같은 구조 [확인됨])

**각인가 사망해도 남는다.** 덕코프의 토템과 근접 무기가 그렇다. [확인됨]
"전부 잃어도 맨몸으로 다시 시작할 수 있다"는 안전망이며 **영구 진행 레이어**를 만든다.
Blob에서는 **도감 + 계정 레벨 + 각인** 3가지가 그 역할을 한다.

**시체 회수** — 계정 트리 「시체 회수 I」를 열면 추출 실패 시 **단 한 번** 되찾으러 갈 수 있다. 되찾으러 가다 다시 죽으면 이전 시체는 사라진다. [확인됨]
→ "복구하러 갈까, 포기할까"라는 두 번째 추출 판단이 생긴다.

### 9-2. 엔딩이 여러 개다

> 덕코프는 엔딩 업적이 4개다. [확인됨]
> 「생존자」 「움직이는 표적」 「살아서 탈출하기」 「제9구역」

**끝을 하나로 두지 않는다.** 마지막에 무엇을 아는 상태로 도달했는지가 갈림을 만든다.

| 엔딩 | 조건 | 뜻 |

### 9-3. 「재능」은 도입하지 않는다

덕코프 업적에 **재능(광전사 / 사격수 / 운반자 / 생존자)** 이라는 별도 축이 확인된다. [확인됨]
(위키에 상세 페이지가 없어 내용은 [확인 불가])

**Blob은 넣지 않는다.** 이미 축이 넷이다 — 장비 · 인자 · 각인 · 패시브.
다섯 번째를 넣으면 어느 축을 올릴지가 아니라 무엇이 무엇인지를 외우는 게임이 된다.
