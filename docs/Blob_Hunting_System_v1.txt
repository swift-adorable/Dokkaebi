0. 이 문서가 다루는 것
--------------------------------------------------------------------------------
"적을 어떻게 만나고, 어떻게 죽이고, 무엇을 얻는가"를 정의한다.

  등급 (PoE2)  →  속성 (PoE2)  →  드랍  →  AI  →  배치

Skill 시스템이 "무엇으로 죽이는가", 장비 시스템이 "무엇을 입고 가는가"라면
사냥 시스템은 "무엇을 상대하는가"다.

1. 몬스터 등급 — PoE2 체계 도입
--------------------------------------------------------------------------------

| 등급          | 속성 수 | 이름           | 표시            |
|---------------|---------|----------------|-----------------|
| **일반**      | 0       | 없음 (종족명)  | 기본            |
| **마법**      | 1~2     | 없음 (종족명)  | 푸른 윤곽       |
| **희귀**      | 3~4     | 고유 이름 생성 | 노란 윤곽 + 오라 |
| **고유(보스)**| 고정    | 고정 이름      | 전용 연출       |

[근거 — poe2db 원문]  [확인됨]
  "몬스터 속성 하나당 떨어지는 아이템의 희귀도가 100% 이상 증가하며,
   몬스터가 추가 능력이나 영구적인 버프를 획득하기도 합니다."

  → 등급이 곧 드랍 품질이다. 별도의 드랍 테이블을 만들 필요가 없다.
     속성 수를 정하면 드랍 등급이 따라온다.

[Blob 적용 시 주의]
  · PoE2는 271종의 몬스터 속성을 가진다. Blob은 그만큼 둘 수 없다.
    12종으로 시작하고 필요하면 늘린다. (3절)
  · PoE2의 희귀 몬스터는 화면을 가득 채우는 이펙트를 쓴다.
    Blob은 모바일이므로 윤곽선 + 소형 오라로 제한한다.
  · 등급 표시는 색만으로 구분하지 않는다. 색각 이상 유저를 위해
    윤곽 두께와 아이콘을 함께 쓴다.

--------------------------------------------------------------------------------
2. 「변이체」 개념 폐지 — 등급 시스템으로 흡수
--------------------------------------------------------------------------------
기존 기획의 「변이체(Mutant)」는 "변이 샘플을 떨구는 특별한 적"이라는
별도 유형이었다. 등급 시스템을 도입하면 이 개념이 중복된다.

  폐지 전 : 일반 적  +  변이체(별도 유형)
  폐지 후 : 일반 / 마법 / 희귀 / 고유  —  희귀 이상이 변이 샘플을 떨군다

[근거]
  · "특별한 적"을 표현하는 장치가 두 개가 되어 유저가 무엇을 노려야 할지
    헷갈린다.
  · 등급 시스템이 이미 시각 표시·속성·드랍 품질을 전부 제공한다.
    변이체를 따로 두면 그 세 가지를 또 만들어야 한다.
  · 장비 옵션 「변이체 드랍률」이 자연스럽게
    「희귀 이상 적 드랍률」로 바뀌어 다른 스탯과 같은 축에 놓인다.

[유지되는 용어]
  「변이 샘플」은 그대로 쓴다. 도감 해금 아이템의 이름이며,
  등급 시스템과 충돌하지 않는다.

3. 몬스터 속성 — 12
--------------------------------------------------------------------------------
개체 단위로 붙는 수식어다. 등급에 따라 개수가 정해진다.

  ※ 레이드 특성과 혼동하지 않는다.
       레이드 특성 = 맵 전체에 적용. 진입 전 공개. (Skill 시스템 문서)
       몬스터 속성 = 개체 하나에 적용. 만나봐야 안다.

[3-1. 방어형 — 4]
| 속성   | 효과                              | 대응 수단            |
|--------|-----------------------------------|----------------------|
| 경화   | 물리 내성 +50%                    | 속성 피해로 전환     |
| 내화성 | 화염 내성 +50%                    | 다른 속성 / 화염 조율 |
| 절연성 | 번개 내성 +50%                    | 다른 속성            |
| 항체   | 카오스 내성 +50%                  | 다른 속성            |

[3-2. 생존형 — 3]
| 속성   | 효과                                      | 대응 수단        |
|--------|-------------------------------------------|------------------|
| 재생   | 초당 체력 회복                            | 즉발 화력        |
| 껍질   | 첫 피격을 1회 무효화한다                  | 다중 적중        |
| 분열성 | 사망 시 절반 체력의 일반 개체 2마리로 나뉜다 | 광역 정리      |

[3-3. 공격형 — 3]
| 속성   | 효과                                        | 대응 수단        |
|--------|---------------------------------------------|------------------|
| 신속   | 이동 속도 +40%                              | 동결 / 밀어내기  |
| 과민   | 예비동작 0.35초 → 0.2초                     | 더 이른 대시     |
| 육중   | 밀어내기·기절 면역. 대신 이동 속도 -20%     | 거리 유지        |

[3-4. 지원형 — 2]
| 속성   | 효과                                          | 대응 수단      |
|--------|-----------------------------------------------|----------------|
| 전파   | 주변 일반 적의 이동 속도와 공격 속도를 올린다 | 먼저 처치      |
| 잔향   | 사망 시 자신의 속성 1개를 주변 적에게 넘긴다  | 처치 순서 조절 |

  ※ 「과민」이 특히 중요하다. Blob의 핵심 방어 동사가 대시 회피이고
     EnemyAttack이 "예비동작 → 판정 시 사거리 재확인" 구조이므로,
     예비동작 단축은 유저의 반응 타이밍을 직접 흔든다.
     수치를 함부로 올리지 않는다. (TBD)

  ※ 속성 조합 금지 규칙
       경화 + 내화성 + 절연성 + 항체 를 동시에 붙이지 않는다 (공략 불가)
       희귀 등급의 방어형 속성은 최대 2개까지.

4. 드랍
--------------------------------------------------------------------------------

[4-1. 드랍 품질 — 속성 수에 연동]
poe2db 원칙을 그대로 쓴다. 속성 1개당 드랍 아이템 희귀도가 크게 증가한다.

| 등급 | 속성 수 | Biomass | 장비 드랍            | 변이 샘플        |
|------|---------|---------|----------------------|------------------|
| 일반 | 0       | 기본    | 티어 1~2 낮은 확률   | 없음             |
| 마법 | 1~2     | ×1.5    | 티어 2~3             | 없음             |
| 희귀 | 3~4     | ×3      | 티어 3~5             | 확률 드랍        |
| 고유 | 고정    | ×6      | 티어 4~6 (내구도 손상) | **확정 드랍**  |

  ※ 구체 수치는 TBD. 위 표는 비율의 방향만 확정한다.
  ※ 고유(보스) 드랍 장비의 내구도가 깎여 있는 것은 Duckov 규칙이다. [확인됨]

[4-2. 변이 샘플 — 도감 해금]
        희귀 이상 적 처치
          → 「변이 샘플」 드랍 → 흡수
          → 추출 성공 : 도감에 영구 등록
             추출 실패 : 샘플 소실 (기존 도감은 유지)

  이 구조가 추출 게임의 긴장을 만든다.
  미해금 샘플을 들고 있을 때 "지금 나갈까, 더 돌까"가 성립한다.

  ※ 장비 옵션 「희귀 이상 적 드랍률 +N%」이 이 축을 직접 강화한다.
     그 장비를 끼는 것은 "이번 레이드는 화력보다 수집을 우선한다"는 선언이다.

[4-3. 잃는 것과 잃지 않는 것]
  추출 실패 시 잃는 것    : 착용 장비, 가방 내용물, 미등록 변이 샘플
  추출 실패 시 유지되는 것 : 도감, 적재 슬롯 수

  장비 = 리스크 / 도감 = 안전장치. 이 분리가 이탈을 막는다.
  (Duckov의 개(dog) 슬롯과 같은 역할)

5. 적 배치 — 설계 전제
--------------------------------------------------------------------------------
Duckov의 구조를 그대로 따른다. 임의 해석 금지.

  · 적은 맵 전역에 넓게 분산 배치된다. 총량은 맵마다 다르다. [확인됨]
  · 플레이어가 탐험하면서 소규모로 점진적으로 조우한다.
    "동시에 수십 마리가 한꺼번에 추격하는 군집 생존 게임이 아니다."
  · 전투 형태는 [소규모 조우의 반복 + 탐험]이며,
    플레이 시간의 상당 부분을 이동과 탐색이 차지한다.
  · 루팅과 적 배치는 매 출격마다 무작위 재배치된다. [확인됨]

  ※ EnemyManager의 "동시 생존 상한 60"은 【성능 상한값】이다.
     "동시에 60마리가 추격한다"는 뜻이 아니다.

[5-1. 등급 분포 — 맵 1회 기준]
| 등급 | 비율 목표      |
|------|----------------|
| 일반 | 약 75%         |
| 마법 | 약 20%         |
| 희귀 | 약 4~5%        |
| 고유 | 맵당 1~2체 고정 |

  ※ 수치는 TBD. 희귀가 너무 흔하면 도감 해금이 빨라져 페이싱이 무너지고,
     너무 드물면 레이드를 도는 이유가 사라진다.

[5-2. 조우 단위]
  · 일반·마법은 2~5마리 단위로 배치한다
  · 희귀는 단독 또는 일반 3~4마리를 대동한다
     → 「전파」 속성이 붙은 희귀는 대동한 적을 강화하므로 우선 처치 대상이 된다
  · 고유(보스)는 지정된 구역에 고정 배치한다

[5-3. 현재 구현과의 차이]
  현재 `EnemySpawner`는 2초 간격 · 반경 12m 원주 스폰 · Prewarm 16이다.
  이는 임시 테스트용이며, 위 설계와 정면으로 어긋난다.
  9단계 스테이지 구현 시 【맵 전역 사전 분산 배치】로 교체한다.

6. 적 행동 (AI)
--------------------------------------------------------------------------------

[6-1. 현재 구현]
  EnemyMovement : NavMesh 미사용. Rigidbody 직접 추격 + 밀집 방지(separation)
  EnemyAttack   : 사거리 1.6m 진입 → 예비동작 0.35초(정지) → 판정 → 쿨다운 1.2초
                  판정 시점에 사거리를 재확인하므로 대시로 회피하면 빗나간다
  EnemyController : Health 이벤트 구독으로 사망 처리, 시체 생성, 풀 반납
  EnemyManager  : 활성 적 추적, 플레이어로부터 40m 초과 시 자동 반납

[6-2. 텔레그래프 구조 — 확정 기획]
  "예비동작 → 판정" 구조를 유지한다. 접촉 데미지가 아니다.
  판정 시점에 사거리를 재확인하는 것이 핵심이다.
  이 구조 덕분에 다음이 전부 성립한다.

    · 대시 회피가 유효하다
    · Core 「충격파」의 밀어내기가 능동 방어 수단이 된다
    · 몬스터 속성 「과민」(예비동작 단축)이 실질적 위협이 된다
    · 몬스터 속성 「육중」(밀어내기 면역)이 충격파의 대응책이 된다

  ※ 시각 신호(windupIndicator)는 미구현이다. Duckov는 빨간 플래시를 쓴다.
     구현 전까지 「과민」 속성을 붙이지 않는다. 보이지 않는 단축은 불공정하다.

[6-3. 미구현 / TBD]
  · 시야 콘(vision cone) — Duckov의 핵심 긴장 장치
  · 오디오 텔레그래프 — 발소리·총성으로 위치 파악
  · 팩션 AI (적끼리 싸움) — Duckov에 있으나 Blob 도입 여부 미정
  · 감지 파라미터 (Duckov 참고치: 시야거리 12~22, 시야각 100~150도,
    반응시간 0.1~0.5초) [불확실]

7. 레이드 특성과의 관계
--------------------------------------------------------------------------------
레이드 특성은 맵 전체에 적용되고, 몬스터 속성은 개체에 적용된다.
두 축은 곱해진다.

  예) 「경화 외피」 레이드 + 「경화」 속성이 붙은 희귀 적
      → 물리 내성이 이중으로 겹친다

[중복 완화 규칙]
  레이드 특성이 이미 부여하는 내성과 같은 계열의 몬스터 속성은
  해당 레이드에서 출현 확률을 낮춘다. (수치 TBD)
  이 규칙이 없으면 "속성 봉인 레이드에서 그 속성 빌드가 아예 못 싸우는" 구간이 생긴다.

[레이드 특성 10종 — Skill 시스템 문서와 공유]
  밀집 서식 / 산개 순찰 / 경화 외피 / 재생 조직 /
  내화 피부 / 저온 적응 / 절연 피막 / 면역 항체 / 응고 혈액 / 부식 대기

  ※ 「밀집 서식」과 「산개 순찰」은 동시에 부여되지 않는다.
  ※ 「밀집 서식」은 5-2의 조우 단위를 크게 만든다.
     이때 전령(처치 시 연쇄)이 최대 가치를 낸다.

8. 데이터화
--------------------------------------------------------------------------------
- 몬스터 등급은 enum. 속성은 ScriptableObject로 정의한다.
  위치: Assets/Data/ScriptableObjects/MonsterMods/
- 등급별 속성 수와 드랍 배율은 ScriptableObject(스폰 테이블)로 분리한다.
  코드에 하드코딩하지 않는다.
- 속성 부여 로직은 MonoBehaviour 의존 없는 순수 클래스로 분리한다.
  (MonsterModRoller — 시드를 받아 결정적으로 동작. EditMode 테스트 대상)
- 이름 생성기(희귀 등급)도 순수 클래스로 분리한다.

[클래스 구성 (예정)]
  Assets/Scripts/Core/Hunting/
    MonsterRarity.cs        일반 / 마법 / 희귀 / 고유
    MonsterModType.cs       속성 enum 12종
    MonsterModDefinition.cs 속성 정의 SO
    MonsterModRoller.cs     등급 → 속성 추첨. 순수 클래스
    MonsterNameGenerator.cs 희귀 이름 생성. 순수 클래스
    DropTable.cs            등급 → 드랍 품질. 순수 클래스
    SpawnTable.cs           맵별 등급 분포 SO
