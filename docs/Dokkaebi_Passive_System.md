# Passive System

> **담당** — 계정이 배우는 것 · 파밍을 넘어 남는 것
> 조사 기록: [`research/duckov_스킬.md`](research/duckov_스킬.md)

전투 수치는 이 문서에 **없다** — 그것은 [`Equipment_System.md`](Dokkaebi_Equipment_System.md)의 몫이다. **그 경계가 이 문서의 핵심이다.**

## 0. 절대 규칙 — 패시브는 전투 수치를 주지 않는다

방어도 · 방어 관통 · 피해 · 최대 체력 · 이동 속도 · 시야 · 감지 · 대시는 **전부 장비**다.

> 덕코프는 이 경계를 지키지 않는다 — 「스킬 강화」 44칸 중 34칸이 전투 수치다. [확인됨]
> Dokkaebi가 따르지 않는 이유는 **장비 옵션이 25종**이기 때문이다. 패시브가 같은 축을 건드리면 장비를 고르는 결정이 통째로 사라지고, 성장 축 넷 중 하나가 죽는다.

검사는 문서가 아니라 테스트가 한다 — `PassiveStateTests.패시브_효과에_전투_수치가_없다`가 `PassiveEffectType` enum 이름에서 전투 단어(Armour · Damage · Health · Move · View · Detect …)를 막는다. **문서에만 적힌 규칙은 언젠가 "방어력 +5 하나쯤이야"로 무너진다.**

| 축 | 여는 것 | 잃는가 |
|---|---|---|
| **레벨** | 소켓 · **패시브 요구 레벨** | **영구** (결정 2-33) |
| 장비 · 젬 · 각인 | 전투 능력 | 각인만 사망에 남는다 |
| **패시브** | 휴대 · 수집 · 회수 · 경제 · 해금 | **영구** |

> 예전에는 패시브를 따로 있던 「계정 레벨」이 열었다. 오르는 길이 없어 디버그 버튼으로만 바뀌던 값이다.
> 이제 **레벨 하나**가 소켓과 패시브를 함께 연다.

## 1. 계열 5갈래 — 단일 트리를 쓰지 않는다

단일 트리는 "위로 한 줄"뿐이라 플레이어가 고를 것이 순서밖에 없다. **계열이 갈리면 파밍 성향이 갈린다.**

| 계열 | 무엇을 | 해금 조건 |
|---|---|---|
| **적응** | 얼마나 들고 나가는가 | 레벨 |
| **대사** | 얼마나 얻는가 | 레벨 |
| **회수** | 죽어도 무엇이 남는가 | 레벨 |
| **중개** | 벙커에서 무엇을 하는가 | **골드만** (레벨 무관) |
| **역행** | 숨겨진 것 | **조우해야 계열이 보인다** |

덕코프의 「신체 단련」 계열은 통째로 가져오지 않는다 — 전부 장비의 축이다. 그 자리를 Dokkaebi 고유의 **회수**가 대신한다. 철수 루팅 게임에서 「죽어도 무엇이 남는가」는 휴대만큼 큰 결정이다.

## 2. 해금 조건 3종

| 종류 | 계열 | 규칙 |
|---|---|---|
| `Level` | 적응 · 대사 · 회수 | 레벨 + 골드 + **필요 재료** (식별자 이름은 에셋 호환을 위해 그대로) |
| `CreditsOnly` | 중개 | 레벨을 보지 않는다. 돈만 있으면 연다 |
| `Discovery` | 역행 | **계열 전체가 조우 전까지 보이지 않는다** |

> 조우 해금의 근거 — 덕코프 「이상한 개조」는 지하실 열쇠 → 독가스 구역 통과 → 갈림길 열쇠 → 수상한 상인 조우로 열린다. [확인됨] 레벨도 돈도 아니고 **「거기까지 갔는가」**가 조건이다.
> Dokkaebi에서 무엇을 어디서 만나야 열리는지는 **미정**이다. 이전 세계관의 「4장 봉인된 관측실의 역행자」는 폐기했다 (결정 2-39). → [`Story.md` 9절](Dokkaebi_Story.md) TBD 2번

## 3. 필요 재료 — 골드만으로는 열리지 않는다

```
하위 칸  : 골드만
중간 칸  : 골드 + 흔한 재료 (쇠붙이 · 새끼 뭉치)
상위 칸  : 골드 + 귀한 재료 (노리개 · 약재)
```

골드만 쓰면 시간을 들이면 전부 열린다 — 결정이 없다. 재료를 요구하면 **"이 노리개를 팔까, 패시브에 쓸까"**가 생긴다. 파밍이 성장에 직접 닿는다.

## 4. 트리 모양 — 세 패턴

| 패턴 | 만드는 것 | Dokkaebi 적용 |
|---|---|---|
| **다이아몬드** (갈렸다 합류) | 순서에 결정 | 각 계열에 최소 1개 |
| **교차 선행** (두 계열을 동시에 요구) | 한 갈래만 파면 닿지 않는 칸 | 역행 계열 |
| **계단** (같은 효과 반복) | 고민 없이 쌓는 갈래 | 중개 계열 전체 |

> 전부 결정이면 피로하다. 하나쯤은 단순해야 한다.

## 5. 효과 목록

전부 비전투다. 새 효과를 추가할 때는 **"이것이 전투 중에 적용되는가"**를 먼저 묻는다.

**적응 — 휴대**

| 효과 | 설명 | 제한 |
|---|---|---|
| `CarrySlots` | 가방 칸 | **패시브 총합 ≤ 장비 최대치의 1/2** |
| `CarryWeight` | 최대 소지 중량 | 같은 제한 |

> 겹치는 축에 상한을 두는 이유 — 가방 티어 6종을 고르는 결정이 남아야 한다.

**1/2 라는 숫자의 근거** — 덕코프 퍽은 가방 공간 +31칸 / 소지 중량 +37kg를 준다.
장비 쪽 최대치(가방 +30칸 / +30kg)와 거의 **1:1**이다. 다만 Lv.17~40에 걸쳐
열리는 후반 축이라, 초중반에는 장비가 사실상 전부다.
Dokkaebi는 그 1:1을 그대로 쓰지 않고 절반에서 끊는다. 우리 가방은 티어마다 성격이
달라서(고중량형 30kg/10칸 · 소형물형 12kg/24칸) 「무엇을 담을 것인가」가 티어 선택의
본체이고, 패시브가 1:1로 따라붙으면 그 성격 차이가 묻힌다.

| 축 | 패시브 총합 | 장비 최대치 | 비율 |
|---|---|---|---|
| 칸 | 8 (2+3+3) | 37 (가방 t6 30 + 몸통 t1 경량 7) | 22% |
| 중량 | 15 (6+9) | 30 (가방 t6) | 50% |

> 이 표는 `PassiveCapacityTests`가 강제한다. 값을 올리려면 테스트가 먼저 막는다.

**대사 — 수집**

| 효과 | 설명 |
|---|---|
| `AbsorbAmount` | 경험치 획득 +n% |
| `AbsorbRange` | 흡수 감지 범위 +n |
| `LootRolls` | 시체 전리품 추첨 +n회 |
| `RareDropRate` | 희귀 드롭 +n% |

**회수 — 죽어도 남는 것**

| 효과 | 설명 |
|---|---|
| `SafeSlots` | 사망해도 지키는 가방 칸 +n |
| `CorpseRecovery` | 【해금】 철수 실패 시 내 시체에서 1회 회수 |
| `ExtractMark` | 【해금】 지도에 철수 지점 상시 표시 |

> `SafeSlots`는 **규칙 하나(죽으면 들고 있던 것 전부)의 유일한 예외**다. 예외를 늘리지 않기 위해 이 계열 밖에 두지 않는다. 각인이 사망에 비유실인 것은 아이템 속성이지 패시브가 아니다.

**중개 — 벙커 경제**

| 효과 | 설명 |
|---|---|
| `SellPrice` | 판매가 +n% |
| `StashSlots` | 창고 칸 +n |
| `ShopRefresh` | 상점 갱신 쿨다운 −n% |
| `ShopSlots` | 상점 갱신 횟수 +n |

**역행 — 숨겨진 것**

| 효과 | 설명 |
|---|---|
| `CraftBench` | 【해금】 제작대 |
| `CodexAuto` | 【해금】 처치만 해도 도감 등록 (샘플 흡수 불필요) |
| `GemSalvage` | 【해금】 젬을 분해해 재료로 |
| `MapLoot` | 【해금】 지도에 전리품 위치 표시 |

## 6. 금지 사항

1. **전투 수치를 주지 않는다** — 방어도·관통·피해·체력·이동·시야·감지·대시
2. **새 예외를 만들지 않는다** — 사망 규칙의 예외는 `SafeSlots` 하나뿐
3. **초기화(리스펙)를 넣지 않는다** — 되돌릴 수 있으면 고를 때 고민하지 않는다
4. **계열을 6개 이상으로 늘리지 않는다** — 화면 한 장에 들어와야 한다
5. **같은 효과를 두 계열에 두지 않는다** — 어느 갈래를 팔지가 흐려진다
6. **패시브로 젬을 주지 않는다** — 젬은 파밍으로만 얻는다
