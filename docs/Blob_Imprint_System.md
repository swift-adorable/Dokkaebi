# Imprint System — 각인(刻印)

> **담당** — 죽어도 남는 유일한 장착품 · 「무엇을 깎아 무엇을 얻는가」
> **근거** — 덕코프 토템 69종 (조사: [`research/duckov/01_토템.md`](research/duckov/01_토템.md))

수치의 출처는 [`Combat_Baseline.md`](Blob_Combat_Baseline.md)다. 이 문서는 **규칙과 목록**만 정한다.

## 0. 이 시스템이 풀어야 하는 문제

각인은 **추출에 실패해도 잃지 않는** 유일한 장착품이다.
(Progression 6절 / `ItemDefinition.SurvivesDeath`)

그래서 질문이 하나 생긴다 — **잃지 않는데 무엇을 줘야 하는가?**

순증(방어도 +5, 피해 +10%)을 주면 **죽어도 사라지지 않는 전투력**이 된다.
장비를 잃는 것이 안 아파지고, 「죽으면 들고 있던 것 전부」라는 이 게임의 뼈대가 물러진다.

### 절대 규칙 — 각인은 순증을 주지 않는다

> **각인은 전부 「A를 깎아 B를 얻는다」이다. 예외는 없다.**

강해지는 것이 아니라 **모양이 바뀐다.** 잃지 않아도 안전한 이유가 여기 있다.

> 덕코프 토템은 Ⅰ·Ⅱ가 순증이고 Ⅲ에만 대가가 붙는다. [확인됨]
> 우리는 **전 단계에 대가를 건다.** 토템은 죽으면 잃지만 우리 각인은 잃지 않기 때문이다.
> 조건이 다르면 규칙도 달라야 한다.

## 1. 슬롯

| 항목 | 값 |
|---|---|
| 슬롯 수 | **2** (`EquipmentSlot.ImprintA` / `ImprintB`) |
| 중복 | **같은 계열 + 같은 단계**는 두 개 못 낀다 (`EquipmentLoadout`) |
| 무게 | **0.3 고정** — 각인은 무게 결정을 만들지 않는다. 슬롯이 결정이다 |
| 사망 | **잃지 않는다** |
| 거래 | 불가 (덕코프 「귀속 장비」와 같다) |

같은 계열의 다른 단계는 낄 수 있다 — 「진격 Ⅰ + 진격 Ⅲ」은 허용한다.
누적 대가가 커지므로 스스로 억제된다.

## 2. 단계 — Ⅰ / Ⅱ / Ⅲ

| 단계 | 이득 | 대가 | 가치 |
|---|---|---|---|
| **Ⅰ** | 작다 | 작다 | 350 |
| **Ⅱ** | 보통 | 보통 | 1,000 |
| **Ⅲ** | **크다** | **크다 — 종종 다른 축을 건드린다** | 3,500 |

Ⅲ의 대가는 같은 축이 아니라 **다른 축**을 깎는다.
「피해를 얻고 사거리를 잃는다」가 아니라 「피해를 얻고 **체력이 계속 준다**」로 간다.
그래야 Ⅲ을 두 개 끼는 선택이 실제로 위험해진다.

## 3. 계열 8종

Blob은 총기 중심이고 허기·갈증이 없다. 덕코프의 근접·수분·에너지 계열은 가져오지 않는다.

| 계열 | Ⅰ | Ⅱ | Ⅲ |
|---|---|---|---|
| **진격** | 피해↑ / 사거리↓ | 피해↑↑ / 사거리↓↓ | 피해 극대 / **체력 지속 감소** |
| **관망** | 사거리↑ / 이동 속도↓ | 사거리·시야↑↑ / 이동↓↓ | 사거리 극대 / **근거리 피해 증가** |
| **경량** | 이동↑ / 최대 체력↓ | 이동·대시↑↑ / 체력↓↓ | 이동 극대 / **방어도 0 취급** |
| **중장** | 방어도↑ / 이동↓ | 방어도↑↑ / 이동↓↓ | 방어도 극대 / **대시 불가** |
| **연소** | 상태이상 위력↑ / 직접 피해↓ | ↑↑ / ↓↓ | 위력 극대 / **직접 피해 절반** |
| **정밀** | 치명↑ / 발사 간격↑ | ↑↑ / ↑↑ | 치명 극대 / **탄창당 1발** |
| **포식** | 경험치↑ / 최대 체력↓ | 경험치·흡수 범위↑↑ / 체력↓↓ | 경험치 극대 / **회복량 0** |
| **역치** | 한 상태 면역 / 그 속성 저항 −50% | 두 상태 면역 / 두 속성 저항 −50% | 세 상태 면역 / **해당 속성 피해 2배** |

### 역치 계열이 특별한 이유

덕코프 토템의 저항 계열은 **수치가 아니라 면역**을 판다. [확인됨]
「점화 면역」 「중독 면역」 「출혈 면역」.

우리도 같게 간다. 다만 **면역의 대가는 그 속성에 더 약해지는 것**이다.
점화에 면역이 되는 대신 화염 피해 자체는 더 아프게 받는다 —
**상태는 막고 피해는 받는다.** 이 구분이 우리 DamageResolver와 StatusEffect의 분리를 드러낸다.

## 4. 획득

| 경로 | 규칙 |
|---|---|
| 드랍 | 희귀 이상 등급의 적. 단계가 높을수록 드물다 |
| 상인 | 벙커 잡화 상점에서 Ⅰ·Ⅱ 판매. **Ⅲ은 팔지 않는다** |
| 제작 | 작업대 해금 후. Ⅲ은 Ⅱ 두 개를 녹여 만든다 |

**Ⅲ을 살 수 없게 하는 이유** — 돈으로 극단을 사면 결정이 아니라 구매가 된다.

## 5. 절대 금지 사항

1. **순증을 주지 않는다.** 예외 없다. 대가 없는 각인은 만들지 않는다.
2. **인자(스킬)가 하는 일을 주지 않는다.** 각인은 수치와 면역만 건드린다.
   메커니즘을 바꾸는 것은 인자의 몫이다. ([`Skill_System.md`](Blob_Skill_System.md) 14절)
3. **패시브가 하는 일을 주지 않는다.** 가방·창고·판매가·해금은 계정 축이다.
4. 슬롯을 3개로 늘리지 않는다. 2개라서 「무엇을 포기하는가」가 성립한다.
5. **사망 비유실의 예외를 각인 밖으로 넓히지 않는다.**
   유일한 다른 예외는 패시브 「보존 칸」 하나다. ([`Passive_System.md`](Blob_Passive_System.md) 5절)

## 6. 데이터화

- `EquipmentDefinition` (kind = `ItemKind.Imprint`)를 그대로 쓴다.
  `imprintFamily` = 계열, `tier` = 단계, `stats` = 이득과 대가(음수)
- **대가는 음수 스탯으로 표현한다.** 별도 필드를 만들지 않는다 —
  합산 경로가 하나여야 "왜 이 수치가 이렇게 나왔는가"를 추적할 수 있다.
- `immunity`로 면역 상태를 지정한다 (역치 계열)
- 「체력 지속 감소」처럼 스탯으로 표현되지 않는 대가는
  `StatusEffectType`을 하나 만들어 상시 부여한다 (덕코프 「토템의 저주」와 같은 방식 [확인됨])
