# 플레이 검증 체크리스트

> **왜 필요한가** — 6-C부터 6-L까지 여덟 번의 커밋이 전부 **컴파일 + EditMode만** 거쳤다.
> 테스트 300건이 초록인데 실제로 눈으로 본 적이 없다.
> 이번 감사가 찾아낸 문제가 정확히 그것이었다 — **계산은 맞는데 연결되지 않은 코드.**
>
> 확인이 끝난 줄은 `[ ]` → `[x]`로 바꾼다. 실패하면 **증상 그대로** 적어 둔다.

## 0. 준비

**먼저 알아야 할 것 — 게임 안에서 장비를 얻을 경로가 없다.**
전리품 표는 재료 5 + 소모품 3뿐이고 상점·제작은 8단계다.
그래서 검증 전용 메뉴를 만들었다. 상점과 드롭이 들어오면 지운다.

```
Blob/Playtest/  ← 전부 플레이 모드에서만 동작한다
  파밍 장비 — 티어 1 한 벌
  파밍 장비 — 티어 6 한 벌
  무기 6종 전부
  각인 24종 전부
  각인 — 진격Ⅱ · 중장Ⅲ · 경량Ⅲ · 정밀Ⅲ
  젬 — 핵심 젬 전부
  젬 — 보조 젬 전부
  젬 — 서리 핵심 젬 · 깊은 상처 · 원거리 사격
  가방 채우기 — 과중량 유발
  현재 능력치 출력
  가까운 적에게 냉각 6중첩 (→ 동결)
  가까운 적에게 감전 6중첩 (→ 마비)
  가까운 적에게 중독 10중첩 (→ 부식)
```

### 실제 기기(빌드)에서는 좌상단 「DEBUG」 버튼을 쓴다 ★

**`Blob/Playtest/` 메뉴는 에디터에만 있다.** MenuItem도 AssetDatabase도 빌드에
컴파일되지 않으므로, iOS 빌드에서는 그 메뉴가 존재 자체를 하지 않는다.
실제 기기에서 장비를 얻을 방법이 하나도 없던 이유다.

빌드에서는 **좌상단의 「DEBUG」 버튼**을 누르면 검증 패널이 열린다. 같은 동작이 전부
들어 있고, 결과도 패널 하단에 글로 나온다 — 실제 기기에는 Console 창이 없다.
개발 빌드(Development Build)와 에디터에서만 컴파일된다.

> **에셋을 추가하거나 이름을 바꾸면 「Blob/Playtest/검증 카탈로그 생성」을 다시 실행하고
> 빌드해야 한다.** 지급 목록은 `Assets/Resources/PlaytestCatalog.asset`에 들어 있다.

### 고친 것을 실제 기기에서 보려면 다시 빌드해야 한다

당연해 보이지만 실제로 이것 때문에 세 번을 헛돌았다.
Unity 에디터에서 고쳐도 **이미 만들어 둔 빌드의 코드는 그대로다.**
증상이 그대로면 먼저 `Build/iOS/Data/Managed`의 날짜를 확인한다.

### 「콘솔」은 Unity 에디터의 Console 창이다

**Window ▸ General ▸ Console** (`Ctrl+Shift+C` / macOS `⌘⇧C`). 띄워 두지 않으면
`Debug.Log`는 아무 데도 나타나지 않는다 — 그래서 메뉴를 눌러도 "아무 일도 없다"로 보인다.

다만 **이제는 콘솔을 띄우지 않아도 된다.** 지급·능력치 메뉴는 결과를 같은 문장으로
**가방 화면 하단 힌트 줄**에 띄우고, 가방 화면을 자동으로 연다.
콘솔은 상태이상·사망 같은 전투 로그를 볼 때만 필요하다.

### 가방 화면을 열면 게임이 멈춘다

`[GameManager] State -> Skill (timeScale: 0)`. 인벤토리는 시간을 멈춘다.
**지급 메뉴는 가방 화면을 자동으로 열므로, 지급 직후에는 게임이 정지 상태다.**
적의 움직임이나 공격을 볼 때는 우상단 **「가방」 버튼으로 화면을 닫아야 한다.**

### 조작 규칙 — 장착과 해제

| 하려는 것 | 누르는 순서 |
|---|---|
| 착용 | 가방에서 장비를 누른다 → **초록색으로 밝아진 자리**를 누른다 |
| 무엇을 꼈는지 본다 | 장비 자리를 누른다 (벗겨지지 않는다) |
| 해제 | 장비 자리를 누른다 → 우측 아래 **「해제」** |

**빈손으로 장비 자리를 눌러도 벗겨지지 않는다.** 예전에는 즉시 벗겨져서,
무엇을 꼈는지 확인하려고 누른 것만으로 장비가 가방으로 돌아갔다.

### 탭마다 보이는 것이 다르다

| 탭 | 가방 격자에 보이는 것 |
|---|---|
| 가방 | 젬이 아닌 전부. 젬이 있으면 제목 옆에 「젬 n개는 젬 탭에」 |
| 젬 | 스킬 젬만. 젬은 칸도 무게도 쓰지 않는다 (2-31) |

### 생존 (2-32)

| 확인할 것 | 어떻게 |
|---|---|
| 수분이 에너지보다 먼저 빈다 | 디버그 「수분·에너지 절반」 후 방치 |
| 탈수·허기 페널티가 걸린다 | 디버그 「탈수·허기 즉시」 → 이동이 느려지고 체력이 깎이는가 |
| 무거우면 빨리 마른다 | 「가방 채우기」 후 같은 시간 방치 — 소모량이 1.4배인가 |
| 굶어도 빠져나갈 시간이 있다 | 허기 3중첩에서 체력 100이 66초 이상 버티는가 |

### 버리기

가방에서 아이템을 고르면 우측 상세 패널 아래에 **「버리기」**가 있다.
누르면 화면 중앙에 팝업이 뜬다 —

| 영역 | 내용 |
|---|---|
| 상단 | 아이콘 · 이름 · 보유 개수 · 총 무게 |
| 중앙 | `0 ~ 보유 개수` 슬라이더 + 오른쪽에 개수 직접 입력 |
| 하단 | 취소 · 버리기 |

땅에 떨어지는 월드 아이템이 아직 없어서 **버리기는 곧 삭제다.**
월드 드롭이 생기면 이 팝업은 「몇 개를 내려놓을까」로 뜻만 바뀐다.

### 적은 두 종류가 나온다

| 유형 | 방식 | 체력 | 피해 | 관통 | 사거리 |
|---|---|---|---|---|---|
| 잡귀 (회색) | 근접 | 20 | 8 | 0 | 1.6m |
| 번개귀 (주황) | **원거리** | 30 | 10 | 1 | 9m |

기본 혼합 비율은 원거리 35%다. `Enemy Spawner`의 `Ranged Ratio`로 바꾼다.
근접만 나오면 전투가 「붙는다 / 뺀다」 두 동작으로 끝나 사거리·각도 판단이 죽는다.

- [ ] **0-1** PlayMode 테스트 9건 실행 (Test Runner → PlayMode → Run All)
  - MCP로는 실행할 수 없다. 도메인 리로드가 연결을 끊는다
  - 실패하면 어느 테스트인지만 적어 두면 된다

## 9-B. 출시 빌드에 개발용이 새지 않는가 — 6-P ★

`#if UNITY_EDITOR || DEVELOPMENT_BUILD`는 **코드만** 감싼다.
씬에 배치된 GameObject는 그 전처리기와 무관하게 빌드에 실린다.
실제로 DEBUG 버튼이 출시 빌드에 노출될 상태였다.

막는 층이 셋이다 — `DebugOnly`(표시) · `DebugOnlyStripper`(빌드 시 제거) ·
`DebugOnlyTests`(표시 누락 감지). 그래도 **눈으로 한 번 확인한다.**

### Development Build를 끄고 켜는 법

Unity 6에서 창 이름이 바뀌었다(`Build Settings` → **`File ▸ Build Profiles`**).
체크박스는 그 창 오른쪽 **Platform Settings** 안의 **Development Build**다.

찾아 헤매지 않도록 메뉴를 만들어 뒀다. 이쪽을 쓰는 편이 안전하다 —

```
Blob/Build/현재 빌드 설정 확인          ← 지금 어느 쪽인지 대화상자로 알려준다
Blob/Build/출시 빌드로 전환 (개발 요소 제거)
Blob/Build/개발 빌드 켜기 (검증 도구 포함)
```

「출시 빌드로 전환」은 Development Build뿐 아니라
**스크립트 디버깅과 프로파일러 자동 연결도 함께 끈다.** 켜진 채로 두면
출시 빌드에 디버거 대기 코드가 남는다.

> **여기서 말하는 빌드는 Unity의 빌드다.** iOS는 Unity가 Xcode 프로젝트를 내보내고,
> 그 뒤 Xcode에서 실제 기기에 올린다. **DEVELOPMENT_BUILD 심볼은 Unity가 내보낼 때 정해진다** —
> Xcode의 Debug/Release 스킴과는 별개이고, Xcode에서 바꿔도 소용없다.
> 설정을 바꿨으면 **Unity에서 다시 내보내야** 한다.

- [ ] **B-1** `EditMode` → `Blob.Tests.DebugOnlyTests` 4건 통과
- [ ] **B-2** `Blob/Build/출시 빌드로 전환` → Unity에서 iOS 내보내기 → Xcode 빌드
- [ ] **B-3** 실제 기기에서 **좌상단 DEBUG 버튼이 보이지 않는가** ★
- [ ] **B-4** 검증 패널을 열 방법이 전혀 없는가 (숫자키 치트도 죽어 있는가)
- [ ] **B-5** `Blob/Build/개발 빌드 켜기` → 다시 내보내면 DEBUG 버튼이 **돌아오는가**
  - 돌아오지 않으면 원본 씬에서 지워 버린 것이다. 되돌려야 한다
  - 평소 작업은 이 상태로 둔다. 출시 직전에만 B-2로 바꾼다

> 개발용 UI의 이름을 바꾸면 `DebugOnlyTests.RequiredDebugOnly`도 함께 고친다.
> 테스트가 깨지는 것이 정상이다 — 그때 출시 노출 여부를 다시 확인하라는 신호다.
